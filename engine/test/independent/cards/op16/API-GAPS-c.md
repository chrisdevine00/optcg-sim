# API gaps: OP-16 independent tests, group C

None of these stopped a test from being written. Each says what the public API leaves open and how the tests cope.

1. **Exact-N picks list only the canonical-first candidates.** For "trash 2 cards from your hand" (OP16-089, 090, 093) the `choose` decision lists only the picks that can start a canonical selection, so a later card appears only after earlier ones are picked. The tests read the reachable sets with `reachablePickSets` (all four cards occur, every set has two cards) and pick by card id (`pickCards`). Wanted: a way to read the whole candidate set.
2. **A "use this effect?" `optional` is the only prompt for an auto effect's "you may".** A "may add the top Life card" step (OP16-107, 116) is asked as an `optional`, not as an "up to 1" `choose`, so "up to 1" and "you may" cannot be told apart from the outside. Tests accept one named kind and fail on any other.
3. **A DON!! cost of one class is paid without a question.** "Rest 6 of your DON!!" (OP16-099) with only active cost-area DON!! asks nothing after the yes, so the tests assert the DON!! counts afterwards (`queries.don`) instead of a payment prompt.
4. **An empty candidate set may be skipped or asked empty.** When nothing qualifies (nothing in the trash, no matching Character) the engine either asks nothing or asks an empty `choose`. The tests accept both (`if (kind(g) === 'choose') { expect(offeredIds(g)).toEqual([]); none(g); }`) and assert the outcome.
5. **Unblockable shows only as the absence of legal blocks.** Against [Unblockable] (OP16-095, 096) the Block Step decision is still asked (only "no block" is legal), so the tests assert `blockers(g)` is empty and the keyword is in `CardView.keywords`.
6. **Scenery must be scripted to cause some game events.** A K.O. of my own Character on my own turn (OP16-103's timing check) needs a scripted opposing K.O. effect: the tests use OP17-101 Caribou as p2's Life [Trigger] (needs p2 hand 1 card). Negation (OP16-115) is observed through `CardView.negated` and OP16-082's static +3 cost.
7. **Leader scenery for {Blackbeard Pirates}.** Only OP16-080 and OP09-081 are {Blackbeard Pirates} Leaders. OP09-081 negates my [On Play] effects, so every {Blackbeard Pirates} condition test uses OP16-080 Teach: its [On your Opponent's Attack] asks an `optional` that cannot be accepted (no [Trigger] card in hand), which `theyKo` answers with `unusable`, and it gives my Characters +1 cost on the opponent's turn.
8. **A played Event is already in the trash while it resolves** (CR 2-7-3). The OP16-101 boundary counts the Event itself (9 cards before the play = 10 during resolution); tests state it in the title.
9. **Revealing is observable only through `CardRevealed` events** (OP16-082, 091, 118); whether the opponent's projection shows the revealed card is not checked here.
10. **Scenario setup caps DON!!:** given DON!! plus cost-area DON!! must be at most 10, so tests that give DON!! at setup reduce `costArea` accordingly.

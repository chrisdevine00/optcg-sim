# OP-16 group A independent card tests: API gaps and observations

- **Readings left unasserted (no answer on file).** OP16-001 (M6b-Q16): whether the "8000 power or more" condition also applies to the [Monkey.D.Luffy] branch; only a 10000-power Luffy (P-061) is asserted as a candidate and a non-Luffy, non-Whitebeard 8000+ Character as a non-candidate. OP16-034 (M6b-Q9): whether Luffy counts itself and how two Characters sharing one other name count; only differences both readings agree on are asserted (one more distinct name +1000, two more +2000, a same-named copy and the opponent's Characters +0). OP16-036 (M6b-Q29): the opposing Leader is used unmodified, so base and current power coincide.
- **"Cannot be rested" (OP16-032 Boa Hancock) is observed only through effects that rest the Character** (OP16-037 Mr.3). Whether such a Character may still attack (attacking rests it) or block (blocking rests it) is a rules question with no answer on file, so it is not asserted.
- **Playing a card emits `CardRevealed` (reason `play`) for that card too.** Tests that assert "nothing is revealed" or "exactly these cards are revealed" therefore filter the rule reveals (play, counter, event, trigger, banish) with `revealedByEffects` in `kit-op16a.ts`.
- **Forced picks are not asked.** A cost pick with exactly as many candidates as cards to pick is resolved by the engine (OP16-008 trashing the only 10000-base Character, OP16-033 resting the only two active cards); with more candidates it is asked. `payCost` / `payRest` in `kit-op16a.ts` answer the prompt when it is asked and do nothing otherwise.
- **An "up to N" with no candidate still asks an empty `choose`** that ends with `done` (OP16-031, OP16-026, OP16-019). `skipEmpty` asserts that it is empty and answers it. A cost-less effect with no candidate and no `up to` choice (OP16-006 with no Character of 4000 or less) asks nothing.
- **Exact-2 picks list only the picks that can start a canonical selection** (OP16-003 revealing two cards): the first pick lists one card, the second the rest, so "offered set" assertions for N = 2 collect the two prompts (`describeEightKCost`).
- **A hand-cost reduction is read through `queries.card(...).cost`** on the instance in hand (OP16-005, OP16-015); there is no separate view of "cost to play".
- **No scripted non-K.O. removal and no scripted way to give an opposing Character power above printed except DON!!** (same limitation as the OP-17 notes); the "base power" tests use OP05-077 Gamma Knife (-5000) to separate base from current power on the opposing side (OP16-010, OP16-011), and an attacker's own given DON!! on the opponent's turn (OP16-013).

# API gaps: OP-16 independent tests, group B

None of these stopped a test from being written. Each says what the public API leaves open and how the tests cope.

1. **Exact-N picks list only the canonical-first candidates.** For "place 2 cards from your hand" (OP16-047) the pending `choose` offers 7 of the 8 hand cards: the last card cannot start a canonical pair, so it appears only as a second pick. The tests assert `>= 7` offered and pick in instance order. Wanted: a way to read the whole candidate set, or an order-free pick.
2. **A sole candidate for a cost pick is resolved by the engine.** When exactly one Character can pay "return 1 of your Characters ..." (OP16-045, OP16-050) or "rest 1 of your {Dressrosa} Leader or Stage" (OP16-043) no `choose` is asked. `payCost` in `kit-op16b.ts` picks if a cost `choose` is pending and does nothing otherwise.
3. **An unpayable optional cost is either not asked or asked with "use" unavailable.** For rest, return and DON!! costs (OP16-043, 059, 070, 071, 076) the engine does not ask at all; for hidden-information costs it asks `optional` with `accept` illegal. `mustBeUnpayable` accepts both and throws if "use" is legal.
4. **"Add up to N DON!!" is a `choose` with purpose `mode` and count options.** The options are the counts as option ids (`"2"`, `"1"`, `"0"`); the question is skipped when the DON!! deck is empty. `donCountOptions` / `takeDon` / `asksDonCount` in `kit-op16b.ts` read and answer it; with a short DON!! deck the options shrink (tests assert the missing ones).
5. **Scenery with its own [On Play]**. The only {Admiral} Characters are OP16-063, 065, 073 and OP17-059, all with an [On Play] that asks something when OP16-060 plays them. The tests answer those prompts by name (`settleOnPlays`: `order`, "no" to Aramaki's optional DON!! -1, DON!! count `mode` picks) and otherwise assert on the board, not on DON!! totals.
6. **Event [Counter] targets are chosen after activation.** `useCounter` then `chooseIfAsked` (OP16-038, 040, 057, 059, 076). An Event whose [Counter] condition fails can still be activated; the tests accept both "offered" and "not offered" there (`canCounterWith`) and assert only that nothing was boosted.
7. **Scenario DON!! totals.** A scenario with DON!! given to cards must reduce `costArea` so cost area + given <= 10 (OP16-054, 055, 058); the setup throws otherwise.
8. **Scripted scenery.** OP09-077 Gum-Gum Lightning (K.O. up to 6000 power, DON!! -2) is the only opposing removal used (OP16-043, 071); OP09-072 Franky and ST10-010 Law are the [Blocker] scenery (OP16-044, 053, 063). OP02-081 Domino shows no [Blocker] keyword in the engine's view, so it is not used as a blocker.

## 2026-11-24 — OP-14 fix round: opponent's-End-Phase duration, "set up to N" count, cost trash counts, [Trigger] conditions (ENGINE_VERSION 0.5.13)

- **R1 (OP14-R1, sev 3).** "Until the end of your opponent's next End Phase" (`untilEndOfOpponentsNextTurn`) created on the opponent's own turn now ends at that turn's End Phase (RL-11: the effect's owner is the non-turn player then). `duration()` records `after: turn - 1` when the effect's controller is not the active player, `after: turn` otherwise; `flow.ts` is unchanged. Created on your own turn it still lasts through the opponent's next turn. OP14-082 Oinkchuck's manual `if opponentsTurn` split is gone (plain duration). Every other script with this duration was checked (OP14-029, 033, 098, 119, 120, OP15-019, 074, 097, EB05-009, 059): all create it on the owner's own turn, so none changes. Only OP14-111 Perona's [On K.O.] on the opponent's turn changes (it was wrong).
- **R2 (OP14-R2, sev 2).** `setActive` of DON!! with an `upTo` pick asks a count (a `mode` choice, most first, "None" last) like `addDon`, whenever at least 1 rested DON!! could be set; an exact set and a case with no rested DON!! ask nothing. Reverses the E-Q11 note "set active is unchanged": there are counter-examples where fewer is better (OP07-023 Caribou, OP13-001 Luffy, the whole "give rested DON!!" family). Scripts are unchanged (they already say `upTo`); the author and independent tests answer the prompt, one new test per card declines or sets fewer. OP14-024 A-1 is resolved for the independent author.
- **R3 (OP14-R3, sev 2; owner decision).** A cost is part of the effect (rules-digest 112, CR 8-1-1), so "a card is trashed from your hand by an effect" includes a card trashed as a cost: OP14-045, 049, 056 now have `includeCosts: true`. This settles the cost half of M6b-Q31 (OP12-040 and ST15-001 are unscripted); the open-question note for Q46 (one event per instruction or per effect) is unchanged.
- **R4 (OP14-R4, sev 1).** No engine change was needed: `giveDon` with n 1 and an exact target already asks the target as a min-0 pick (`done` is legal), so "give up to 1 rested DON!!" (OP14-005, 114) can be declined; the review missed the `done` action. Tests pin it. Consistent with E-Q11: a count prompt is asked only when the count has more than one value, and the min-0 target pick covers the one-DON!! case.
- **Also:** a [Trigger] ability's `conditions` are now evaluated when it resolves, as for `auto` (BACKLOG, OP-13 group 4); the validator already rejected unknown modifier durations and an empty `filter: {}` (tests added).
- **Rejected:** a per-script manual split for every use of the duration (the engine was wrong, not the scripts); a count prompt for `giveDon` n 1 (a second way to decline the same thing); keeping `setActive` automatic.

## 2026-11-24 — Empty "up to" hand picks: no engine skip; OP14-052 and OP14-116 were a test-helper artifact (no ENGINE_VERSION change)

Context: independent tests for OP14-052 Hannyabal (after a trash-3 cost) and OP14-116 Salamander (after a +2000 pick) showed no play pick when no hand card qualified, while OP14-043/047/058 asked it, a suspected severity 4 leak. Finding: the engine asks the pick in every frame. `select` (`effects/run.ts`) skips a hidden-zone pick only when the whole zone is empty and there is no filter and no `restrict`, a public fact (zone size); a `play` always carries `restrict`, and 052/116 carry a filter, so a hand with no match is asked at max 0 with 0 candidates, with or without a cost frame (probe: after the third cost pick the decision is `choose`, purpose effect, max 0). The tests' `payHand`/`pickInst` helpers (`choose` in `kit.ts`) send `done` after the last pick when the choices are empty, so they answered the following empty pick themselves. Decision: no engine change, no version bump, goldens untouched; the two tests now pick raw and are plain `it`; DISAGREEMENTS-b/-d mark the entries resolved. Planted `engine/test/cards/empty-pick-hidden.test.ts` (no cost, and an optional hand cost paid first; two positions differing only in a hidden hand card: asked at max 0 vs 1, and p2's projected view and events equal); with the skip widened to any empty pick it fails 4 of 4 and 13 independent OP-14 tests besides. Already-pushed scripts on main are not affected. Rejected: changing the shared helpers (other independent tests rely on the swallow and would fail), and a new leak-property check (the two-position tests cover the shape; the property already compares permuted hidden cards over random play).

## 2026-11-24 — Static hidden-gate check over every script (no ENGINE_VERSION change)

Context: the OP15 fix round found OP15-002 Lucy asking its "trash any number of Event or Stage" pick only when the hand held one, so the pause told the opponent what the hand held (ADR 0005). The 2,000-game leak property only samples such cases. Decision: `cards/src/hidden-gate.ts` (run over the whole registry by `cards/test/hidden-gate.test.ts`, with planted gates so it can fail) reuses the typed walk in `hidden.ts` and reports a hidden-zone condition that decides whether a prompt is asked: (1) an `auto` with a hidden ability-level condition and a prompt, a cost or `optional`; (2) a `trigger` with one (the owner is always asked about a revealed [Trigger]); (3) an optional `replacement` with one; (4) an `if` whose hidden condition makes `then` and `else` differ in prompts; (5) a `forEach` with a hidden count around a prompt. Not reported: a hidden condition with no prompt in the gated branches (the outcome is public, as the card text says); `activate`, `permanent` and Event [Main]/[Counter] offers (shown to their owner only); an `if` whose branches ask the same prompts. A prompt is a selector `pick` (not `blind`), `may`, `chooseOne`, `lookAtTop`, `draw`/`addDon upTo`, or a DON!! choice. Allowlist `HIDDEN_GATE_ALLOWED` (card/ability, one-line reason) exists and is empty; a stale entry fails the test, so it can only shrink. The sweep of all scripts found two more: OP16-041 Buggy and ST32-003 Dracule Mihawk gated a play-from-hand pick on `exists` in hand; both now gate on a hand of at least 1 card and ask the pick at max 0 (their author tests pin it; the old assertions "nothing asked with no eligible card" were the leak). No independent test changed. Script-only change, goldens unchanged. Rejected: flagging every hidden-reading ability (a public outcome such as "if you have X in hand, draw" is what the card says and cannot be hidden); a runtime assertion in the engine (cannot know what the other player could infer); allowing "the prompt is always followed by a public outcome" implicitly (the prompt comes first and an up-to pick need not produce one), so such a case needs an allowlist line. Limits: a hidden read only inside a Selector filter's number is not walked.

## 2026-11-24 — Hand-zone cost permanents move to a last layer stage (ENGINE_VERSION 0.5.12; OP15-R1)

- **Context:** review OP15-R1. A hand-zone cost permanent sat in stage 1 (cost), and a stage reads only the stages before it, so "If your Leader has 0 power or less, give this card in your hand -2 cost" (OP15-013, OP15-102) read the Leader's power without its power-stage permanents (Sabo printed 5000 with a permanent -1000 and timed -4000: 0 power, read as 1000).
- **Decision:** a new stage 6 holds the cost effects whose source is in hand (`zone: 'hand'`). Its conditions read stages 1 to 5, the fully derived power, so the read is right; no field stage reads a stage above its own, so there is no cycle. `LAST_STAGE` is 6. A field-zone cost permanent stays in stage 1. Goldens re-recorded: only the version string changed.
- **Consequence:** a permanent in stages 1 to 5 no longer sees the discounted cost of a card in hand (no script reads a hand card's cost there). Hand-cost effects read each other without the other's stage 6 discount, so two of them cannot loop.
- **Rejected:** re-reading power at the last stage for hand abilities only (a second evaluation path, still cyclic if the hand cost fed a power condition).
- Also in this fix round: OP15-002 Lucy's pick was gated on the hand holding an Event or Stage (a hidden fact visible through the prompt); the 2000-game leak property caught it. The gate is now the public hand size, so the pick is asked at max 0.
- Also considered and not done (OP15-R7): revealing a card on a `play` frame in the view (`canSee`). It removed the skeleton/view mismatch but fails the leak property "views are invariant under hidden permutations" (the played card is a hidden hand card in the property's model), so it is in BACKLOG instead.

## 2026-11-24 — M6b-2 wave 3: G20 to G29 (ENGINE_VERSION 0.5.11)

- **Context:** wave 3 of the M6b-1 audit (`docs/research/m6b-wave3.md`): the opponent's DON!! given to the opponent's cards, `cannotSetDonActive`, hand-trash and rested timings, `Num` division, `cardPlayed` origin and `via`, per-turn history, `returnDon` for the opponent, the K.O. cause on [On K.O.], and `removed`. It unblocks 44 cards, closing block 5 except OP16-079 (D9) and OP16-080 (D3).
- **Decision:**
  - Per-turn history (`State.hist`, keyed by turn) is recorded only in a game where some script reads it, so every other game's hashes, goldens and replays are unchanged.
  - `by` qualifiers match effects only. Costs count only with `by` omitted (G24) or `includeCosts: true` (G22). G29's `cause` counts costs as effects, as G11 did (RL-16).
  - A hand-trash event fires once per instruction. `removed` watchers form their own batch, queued before the K.O.'d card's [On K.O.].
  - `removed` fires in `moveCard`, so a rule trash (full Character area) matches when `cause` is absent.
  - The K.O. cause travels as an event payload (`ev`) on the pending effect and is checked again at resolution.
  - `giveDon` with `state: 'any'` asks which DON!! kinds only when both exist and not all of them go.
  - The AI lethal bound leaves `cannotSetDonActive` unclassified, so the solver searches.
- **Rejected:**
  - Always recording history: it changes every golden hash.
  - A history field cleared at turn change: keying by turn needs no clearing step.
  - Settling M6b-Q30, Q31 or Q41 now: both readings stay expressible.
  - One batch for removal watchers and [On K.O.]: it needs a `runKo` restructure.
  - Hooking only the K.O. and remove frames: it misses the cost and rule paths.
  - A new `Frame` per K.O.
  - Always asking the DON!! kind.
  - Classifying `cannotSetDonActive` as neutral without a per-shape proof.
- New open questions M6b-Q41 to Q47 are in OPEN-QUESTIONS.

## 2026-11-24 — `giveDon` with `each` asks the targets and a count per target (ENGINE_VERSION 0.5.10)

- **Context:** the ST block 5 review (STB5-R1, severity 3) showed that the wave 2 rule for "give up to M rested DON!! to each of up to N targets" (the DON!! on hand cap the targets at `floor(DON / M)`, every target gets exactly M) made legal plays unreachable: ST30-014 with 1 rested DON!! could give nothing, and 3 rested could not give 2 + 1.
- **Decision:** the target pick allows up to `min(N, DON available)` targets (a target needs at least 1); then, in pick order, each target is asked a count from `min(M, DON left - targets still to serve)` down to 1, most first (the same `mode` choose that `giveDon` already uses, so UI, projection and AI are unchanged). A range of one value is not asked, so OP14-105 (M = 1) plays as before. Zero is not offered per target because choosing fewer targets already means that (and the reservation keeps every picked target served).
- **Rejected:** keeping the cap (a rules error), and a 0 option per target (a second way to say "fewer targets").
- Games recorded before are unchanged in play (the three goldens differ only in the version stamp).

## 2026-11-24 — Random Standard decks in the property games; a replacement-offer leak fixed (ENGINE_VERSION 0.5.9)

- **Random Standard decks** (`randomStandardDeck`, `standardDecksFor` in `engine/test/support/decks.ts`): a Standard Leader and 50 Standard-legal cards in its colours, scripted cards weighted 6:1, restricted limits, banned pairs and deck clauses respected, validated with `deckIssues(..., 'standard')`. `standard-games.test.ts` (invariants, replay, listed and unlisted actions), both leak properties and the skeleton diff now run on them too (60 games per push, 10,000 nightly), with seed and decks logged on failure. ## 2026-11-24 — The owner orders cards placed at a deck bottom from hand or trash; a hand-to-deck leak fixed (ENGINE_VERSION 0.5.8)

Context: the OP-16 review (OP16-R3, disagreement B-1) found that "place N cards from your hand at the bottom of your deck in any order" gave the owner no order choice: `run.ts` asked only for cards leaving the field. Decision: several cards of one owner placed at a deck bottom always get the owner's `order` decision, whatever the source zone (field, hand, trash) and whether it is an effect or a cost (OP17-095's replacement payload included); no script flag, the same rule the field case used, so future "in any order" cards need nothing per card. This supersedes the 2026-11-16 note that OP17-095's payload has no order decision. **A hidden-information leak was fixed with it (severity 4 class):** a hand card moved into a deck was marked `revealed`, which named it in the opponent's projected events (OP16-047 and OP17-053 make the opponent bottom two hand cards). Hand cards going into a deck are no longer revealed; trash cards stay public. Planted tests in `engine/test/cards/m6b-order/` include a projection check that fails with `revealed` put back. The nightly leak property did not catch it because it plays meta decks only, which run neither card: the random-Standard-deck nightly games (an M6b done criterion) come next. Also from the OP-16 review (OP16-R7): author tests for the OP16-081 cost boundary and OP16-104 power vs base power, each seen to kill its mutation. Goldens re-recorded for the version string only.

## 2026-11-24 — E-Q11 revisited: "add up to N DON!!" asks a count (ENGINE_VERSION 0.5.7)

Context: E-Q11 (2026-10-29, kept at M4b) let `addDon` add the maximum without asking, on the reasoning that more DON!! is never worse and no card needed fewer. The OP-17 review (OP17-R2) disproved it: 38 Standard cards compare your DON!! count with the opponent's ("equal to or less than", "at least N less"), so a forced add can switch your own cards off (OP17-068 or OP17-078 with OP06-061/063/065/069 or EB04-038; two EB05-033 in one turn). Decision: an `addDon` part with `upTo: true` (already on all 20 scripts that use it) asks a count, most first, with "None" last, reusing `giveDon`'s decision (purpose `mode`), so UI, projection, replay and AI needed no change; exact adds and an empty DON!! deck ask nothing; a two-part add asks per part. The count is public. `setActive` stays automatic (no counter-example found). The four `it.fails` that documented E-Q11 now pass; 9 planted tests in `engine/test/cards/m6b-eq11/` (7 fail with the change reverted; 2 guard unchanged behaviour). Pirate and Warlord rollouts take the first option (the most); MCTS can explore fewer; Rookie picks at random, as for every decision. Also: playbook `cite` text quotes types (`"Rocks Pirates"`), so the hidden-name check in explanations cannot match a type that is also a card name. Rejected: keeping E-Q11 (wrong under the rules and now observable); a new DSL field (the scripts already said `upTo`).

## 2026-11-24 — M6b-2 wave 2: ten more engine gaps (ENGINE_VERSION 0.5.6)

Wave 2 of `docs/research/m6b-runtime-audit.md` §4 (D4 and G11 to G19), built by an agent in a worktree and merged after a full suite run (5,733 unit, 234 e2e); detail and revert results in `docs/research/m6b-wave2.md`; planted tests in `engine/test/cards/m6b-w2/`, each seen to fail with its implementation broken. Goldens re-recorded for the bump; hashes identical.

- **Damage replacement (D4, EB05-052 and Gloriosa's shape)** covers the whole damage, offered before any Life card moves (a Double Attack's two cards are one damage), and is offered at 0 Life too, else the card is useless when it matters. A damage frame at 0 Life is pushed only when the defender has a possible replacement, so every other game runs exactly as before. Rejected: per Life card; only while Life remains; always pushing the frame (golden churn). M6b-Q8 stays open.
- **K.O. and leave-field causes:** `effect` includes costs (RL-16), `opponentEffect` excludes your own costs (RL-14), `any` covers only removals that go through the engine's frames (rule moves such as making room are never replaced).
- **Deck-building clauses** (`anyNumberInDeck`, `deckRestriction`) are checked in the single validator `deckIssues`, read from the loaded script or, before scripts load (the deck builder), a static `DECK_RULES` table; a test loads every script and checks the table agrees. Rejected: loading every script in the builder (bundle budget).
- **`oneOf` cost:** the choice comes first, each alternative is its own list of payments (so later DON!! needs are reserved correctly); refused when nested, in a replacement, or more than once per list.
- **giveDon each:** "up to N targets, up to M each" gives the full M to each chosen target.
- Also: `nameIncludes`, distinct-name counts, lookAtTop take to play (through the normal play frames), K.O. on a Stage. Deferred: one Once Per Turn covering two events (OP13-046), the AI deck generator reading deck clauses. Open questions M6b-Q5, Q8, Q9, Q36 left open.

## 2026-11-24 — The Standard pool verified against Limitless (keyword-only cards play fully)

The EB-05 review (EB05-R6) and the independent testers found that unverified cards which print a keyword (for example [Blocker] on ST08-006) have empty `keywords` in the source data, so the engine ignored the keyword: printed keywords reach the engine only through a verification override (E-D7). `cards:verify-meta -- --set <SET>` now takes a whole product (Standard-legal cards only); it was run over all 52 Standard products with unverified cards (about 2,060 Limitless pages, cached in `.cache/m1/limitless/`, one request a second; robots.txt allows). **1,950 cards matched field for field** and got verified overrides with their printed keywords (the M1 method); 110 disagree in some field and stay unverified until their batch is scripted (the runbook's step d.1 settles them). Verified cards: 183 → 2,013. Standard coverage 19.5% → 20.6% (keyword-only cards now count as playing fully). Alternatives rejected: parsing keywords from optcgapi's text (ADR 0006: text is never parsed into behaviour); waiting for each batch (the keyword-only cards would stay wrong in play for months).

## 2026-11-24 — M6b-2 wave 1: ten engine gaps (ENGINE_VERSION 0.5.5)

Context: wave 1 of `docs/research/m6b-runtime-audit.md` §4 (G1 to G10), built by an agent in a worktree and merged after its report and a full suite run; detail and per-gap revert results in `docs/research/m6b-wave1.md`. Each gap has planted tests on vanilla test cards (`engine/test/cards/m6b-w1/`, 44 tests), and each was seen to fail with its implementation broken. Goldens re-recorded for the version bump: hashes and event sequences unchanged.

- **Field costs (G1)** go through the existing removal and K.O. frames with cause `cost` (last-known information, given DON!! returned, [On K.O.] fires), not a plain move; the validator accepts them only for your own Characters and Stage. **A K.O. cost on a protected Character is offered and fails**: earlier costs stay paid and the effect does not resolve (RL-16, "legal but failed payment"); the check is whether the card left the field, so a replaced K.O. fails the same way. Rejected: hiding protected Characters from the choice (cannot express the replaced K.O.).
- **A cost counts as an effect for protection** ("cannot be K.O.'d by effects" stops a K.O. cost; rules-digest 112, RL-16); "by your opponent's effects" stops only the card owner's opponent's (RL-14, OP04-079).
- **`mill` clamps to the deck, and an empty deck loses at once** (RL-26, digest note 274.2). The audit's sentence that milling must never lose by itself contradicted the rulings and was not followed.
- **`cannotBeRested`**: unscoped blocks every rest, own effects, attacks and blocks included (digest 57); the opponent-effect form blocks only a rest by an effect of the owner's opponent.
- **"During this battle" with no battle in progress** creates nothing and asks for no target (any action with a battle duration).
- **One `scope` field on modifiers and one `restrictionMod` mapping** for timed and permanent restrictions, not one modifier kind per scope.
- **Two more shapes refused by the validator** that used to pass and misexecute (a player restriction on a card target; a permanent `cannotDrawByOwnEffects`); no script used them.
- **The lethal bound** counts `cannotActivateBlocker` as a Blocker lost (it was treated as neutral, which would have been unsound); scoped restrictions, `mill`, `activate` and the new costs stay unclassified, so the solver searches instead of trusting the bound.
- **Open questions left open:** M6b-Q12, Q30, Q31 (the mechanisms support either reading; settled when their cards are scripted).

Alternatives rejected: letting the meta PR fail until a person updates expectations (the PR is weekly and machine-made); injecting the meta into `priorFor` (every caller would change, for a test concern). Update the pinned copy only on purpose, with a DECISIONS entry.

## 2026-11-23 — M6b-6 app updates and M6b-7 AI for any Leader

- **App shell (M6b-6).** The service worker precaches every built file (pages, chunks, the per-set card data and effect-script chunks, styles, fonts; not source maps), about 140 files, into `optcg-shell-<build>`, where the build id is a hash of the files' contents (`app/vite.config.ts`). Pages are network-first with the cached `index.html` as the offline fallback; hashed files are cache-first, matched with `ignoreVary` (the preview server's `Vary: Origin` made the module entry miss offline). Old shells are deleted when a new worker activates. Offline is tested (`app/e2e/update.spec.ts`).
- **Updates wait for the player.** The first install takes control at once; a later build installs and waits. The page shell shows "A new version of the app is ready … Reload to update"; the game route renders outside that shell, so the prompt can never appear mid-game, and the app never reloads by itself. Accepting sends `skip-waiting` and reloads on `controllerchange`. An open tab checks for a deploy hourly as well as on navigation. The e2e test "deploys" by rewriting the served `dist/sw.js` with another build id (Playwright routing does not see the browser's fetch of a worker script), at one resolution only.
- **`version.json`** at the site root: build id, build time, cards through (newest booster), card count and fetch time, the meta's as-of date, engine version. The About page (M10) and bug reports read it.
- **IndexedDB records move to M8** ("Review: local save"). Nothing saves records yet, so a store now would have no reader; M8 builds it with its UI. Records already carry the per-game scripts version (M6b-0), so a saved game opens live unless its own cards' scripts changed.

When a prior's Counter cards rest or draw, the explanation says "Their Counter cards could also rest one of your Characters or draw a card, and the line allows for it". Rocks's priors only add power, so E20 and E01 are unchanged.

Alternatives rejected: one placeholder doing everything at once (+power and rest and draw each time: with a draw every use refunds the card, so the defence is unbounded and every Kaido lethal would read as refuted); a choice of hand compositions per search (exponential in the hand and the Life that joins it); a downgrade without a model (it would mark every Kaido proof as unsure). The superseded model stays reachable as `lethal({ mode: 'public', view, model: 'power-only' })` only so the planted test can show a line it proved and the corrected model does not (Kaido at 2 Life, Luffy 5000, Sanji 7000, Zoro 9000, 6 DON!!: the rest card on the second attack removes the third attacker). ## 2026-11-05 — L: what `public` lethal assumes, and how the search is built

Context: ARCHITECTURE §4.4 says the `public` defender's hand is "bounded by public information" and a hidden Life [Trigger] is a chance node; nothing says how to drive the real engine with cards nobody can name.

- **Method.** The search runs on a real `GameState` built with `determinize` from the requesting seat's `SearchView` alone (it cannot read a game: `publicState(view, cards)`), so Blockers, DON!! allocation, on-attack effects (Kaido's −2000, Newgate's +3000), Counters, Triggers and "each hit gives the defender a card" (CR 7-1-4-1-1-2) all come from `reduce`, `legalActions` and `queries`. Hidden defender cards become a **placeholder Character** that costs nothing, has no effect and carries the biggest Counter in the defender's archetype prior (a Character's printed Counter or a [Counter] Event's +power: `biggestCounter`); every other hidden card is a blank. `public` therefore assumes: **(A1)** each hidden defender card is worth at most that one number in defence and nothing else. A Counter Event's DON!! cost and any other effect on it (a K.O., a draw) are ignored, so a proof is at least as strong as one against the real deck, and a refutation may be pessimistic about a real hand. **(A2)** Hidden Life cards are never [Trigger]s inside the search; the chance is a label (`triggerRisk`: C(50−T, k) / C(50, k) averaged over the prior's lists by recency weight, with k the face-down Life cards, all of which a winning line takes). A refutation ignores it (a Trigger can only help the defender). **(A3)** The seat's own deck draws blanks, so an effect that draws is searched but finds nothing. **(A4)** With no sourced list for their Leader the biggest Counter is assumed to be +4000 and the facts say so (`noPrior`). The leak property: `publicState` takes the view and public card data and nothing else, a differential test changes every hidden card of both sides and demands an identical answer (up to handle names), and no hidden card id may appear in the answer.
- **Search.** AND-OR over the engine: the seat's decisions are OR nodes, the defender's every legal answer an AND node, with a transposition table on `summaryHash`, interchangeable cards (same id and state) as one choice, moves largest swing first, and node caps (tests) or wall-clock caps (the app). The Main Phase moves are **macros**, "give k DON!! to X, then attack T with X": **(A5)** DON!! is never given to a card that does not attack next, so a DON!! condition on a Character that helps another card is not searched; `playCard` (only cards with a script or [Rush]: a card the engine knows nothing about does nothing but spend DON!!) and `activate` stay single steps; attacks on Characters are searched only for a Blocker or a scripted Character (**A6**). A refutation is exhaustive under A5 and A6; a cap is `unknown`, never "no lethal".
- **The line.** First a **fixed plan** that wins against every defender answer (a person can follow it without adapting): the search carries the set of states the defender's answers lead to, over simple moves (Leader attacks, "may" effects declined), tightening the DON!! budget until no plan is left and then taking the first plan in order of fewest DON!!, each attack's DON!! from none upward and smaller attacks first. That is why E20's split is 2 / 5 / 0 and E01's is "all 4 on the Leader". If no fixed plan exists the adaptive AND-OR search decides, and a proof there is labelled `oblivious: false` (the line depends on their answers). Alternatives rejected: the fully adaptive search alone (its first proof gave the Leader 2 DON!! after the defender had spent its cards, which is true but cannot be followed or checked as "split 2 / 5 / 0"); a model of the defender's hand as a number (it would restate the rules the engine already knows, and miss Blockers, Newgate and Kaido).
- **A7.** `attackersPossible` (a bound on attackers against Life, counting [Rush] Characters in hand and [Double Attack] anywhere) answers "no lethal, too few attackers" at once and lets review skip hopeless turns. It does not count effects that untap a Character or add an attack, so such a card could make a rare lethal show as refuted; the bound errs only toward searching otherwise.
- **Cost.** About 30 µs a node (the hash and `reduce`). E20 (a proof with 10 DON!!, 3 attackers, a Newgate) takes about 78,000 nodes, 2.3 s, for the plan search; positions with a full hand of scripted playable cards usually hit the cap (`unknown`) at 8,000 to 25,000 nodes. The per-push test caps are node counts; `npm run test:lethal` runs more games and a bigger cap.
- **Engine.** No engine change. Additive only on the AI package: `lethal`, `explainLethal`, `tier1`, `tier2`, `guidedCount`, `checkGuidedCount`, `reviewMissedLethal`, `answerLethal` and the request type.

## 2026-10-29 — M4a effects slice: runtime and API decisions

Context: M4a builds the effect DSL runtime and scripts the Rocks (OP17-039) and Kaido (OP17-058) lists, 37 cards. The independent card-test author reported API gaps (mode choices, Event [Counter] targets, decision sources, DON!! adds, looked-at cards, effect state in views, keyword strings). Each decision below lists what was rejected.

- **Programs, not trees.** Each ability compiles to a flat program (costs, then the effect; if/else, may/ifDid, choose-one modes and delayed bodies become jumps); an effect frame holds an instruction pointer and its locals. Rejected: walking the step tree with a path stack (more state per frame, harder to hash).
- **API additions (additive, frozen shapes unchanged):** `Decision.purpose` (`cost`, `target`, `mode`, `order`, `use`, `replacement`, `characterLimit`), `Decision.source` (card id, ability id, label; `instance` in queries, `handle` in views), `Decision.options` (named options with labels); `pick.choice` may be `{ option: id }` for modes and top/bottom; `order.first` is a listed option id (a card, or `<card>#<ability>` for pending effects); `CardView`/`ViewCard` gain `counter`, `cannotAttack`, `negated`; `ProjectedView` gains `looking`, `known` (now filled), `attackLock`, `delayed`; event types `CardsLooked`, `ModeChosen`, `EffectDeclined`. - **Event [Counter] is `activate` in the Counter Step.** `{ type: 'activate', card, ability }` with the card in hand; costs are paid at activation and targets are chosen while it resolves (CR 8-4-4). `counter` stays for Character Counters only. Rejected: `counter` with a dummy target.
- **Auto with a cost asks first.** If payability depends on the hand (a trash or reveal cost), the `optional` is asked even when the cost cannot be paid, with "use" unavailable and `secret` set, so the opponent learns nothing; a public cost that cannot be paid skips silently. Rejected: asking only when payable (leaks whether the hand holds a matching card).
- **Hidden-zone choices are always asked** (even with no match) and flagged `secret`; `publicCount` marks a pick over a whole hand of public size. With another human watching, `autoSkip` skips a forced pick only when every candidate is visible or the count forces it (M2-19).
- **DON!! by location with counts (E-D4).** A DON!! −X or return asks for classes with counts; it is not asked when one class can pay or every DON!! must go. "Add up to N DON!!" and "set up to N DON!! active" act on as many as possible without asking. Rejected: asking "how many" each time (adding fewer is never better in these decks; it would double the decisions for players and the AI). Logged as open question E-Q11.
- **Pending effects batch per event; a player orders their own.** `order` asks the controller when two or more of their effects from one event wait (Rule Manual "Effect Activation Order"). Two Characters played by one effect (OP17-118) trigger in play order, as separate batches. Rejected: FIFO with no choice.
- **Negation removes printed keywords too** (CR 10-1 calls them keyword effects; CR 8-2-1-1); granted keywords stay (CR 8-2-4). A negated card's [On K.O.] does not activate, and its replacements do not apply (E-Q1's best answer).

- **Blind picks are random.** "Trash 1 card from your opponent's hand" (OP17-075) is chosen face-down by its controller (QA-OP17); the engine picks uniformly with the seeded RNG. Rejected: a positional pick (the hand array order is draw order, so it would leak).
- **Replacement order.** Applicable replacements are offered one at a time in CR 8-1-3-4-2 rank order; each is optional, so declining one and taking the next gives the same choice as ordering them.
- **`derive` never memoizes a state that is being drafted.** A memo taken mid-`reduce` went stale and showed one viewer an old power; the leak property found it.
- **Instance ids start with `$` (M2-22)** so the hash and the leak tests recognise them anywhere, including compound keys.
- **Benchmark:** 5,588 two-turn simulations per second in a worker; ADR 0008 confirmed, no fallback (`docs/benchmarks.md`).

## 2026-10-28 — Design review 1 fixes; AI-turn target stays at 8 s

## 2026-10-28 — Card data from optcgapi.com, not the official card list

## 2026-10-28 — Engine spec corrected to Comprehensive Rules v1.2.1

Context: Track A read CR v1.2.1 (8/28/2026) and found places where PROMPT.md's engine specification is imprecise. Decision: the engine follows the CR; details and rule numbers are in `docs/research/rules-digest.md` "Corrections to PROMPT.md assumptions". In brief: neither player attacks on their own first turn (CR 6-5-6-1); deck-out is a defeat when the deck reaches 0, checked in rule processing, not "failing to draw"; with five Characters out the player trashes one before the new one is placed, and that trash is not a K.O.; power may be negative; the per-player card-count invariant includes a transient "resolving" location for Trigger cards; Refresh and End phases follow the CR's ordered sub-steps with separate expiry for "until end of turn" and "during this turn"; Character counters are free from hand and Event counters cost DON!!; Double Attack against 1 Life does not win; simultaneous loss and unbreakable loops produce a draw result; the keyword set includes [Rush: Character], [Unblockable], [On Your Opponent's Attack], [End of Your Opponent's Turn], [Main], [Your Turn], [Opponent's Turn], DON!! −X and Trash; start-of-game leader effects run before hands are drawn and Life is set after the mulligan; the four-copy limit is per card number across alt arts; DON!! power applies only on its owner's turn, though [DON!! xX] still counts on the opponent's turn. Alternative rejected: implementing PROMPT.md's wording literally.

# M3 screen-reader pass: NVDA + Chrome

**Kind of pass:** scripted (Guidepup), not a human listening pass (accessibility.md §11.2; risk R9: no Windows machine for a human NVDA pass).
**Result:** **FAIL.** One severity 3 finding (F1, focus lost to the page after common moves). Seven severity 2 findings.
**Date:** 2026-10-29.

## How it ran

- **Script:** `app/a11y/src/m3.ts`, the §11.3 steps on the `a11y-m3` scenario (Kaido against Rookie's Kaido, every card M4a-scripted, turn 3, seed 11, AI pace Step).
- **Keys** go through NVDA (Guidepup's NVDA Remote connection), so browse mode, focus mode and NVDA's own single-letter keys apply as for a user.
- **Speech** is every phrase NVDA spoke, from a listener on the same NVDA Remote channel. Live-region writes and the focused element come from the page.
- **Setup:** fresh browser profile; NVDA defaults. The page is loaded once for Guidepup to find the window, then loaded again before step 1.
- **Turn 3, not turn 1** (scenario comment and DECISIONS): on turn 1 step 7's "played this turn" reason is hidden by "no battles on the first turn". The board therefore reads "turn 3".
- **Step order:** Rookie attacked with its Leader first (step 11's [Trigger] hit), then with King at 7000 (step 10's counters). So step 11 ran before 10, and step 14's order decision came up inside step 12's attack.
- **Harness assists:** none in steps 1–17. In step 18 the harness put focus on each attacker five times; the keys after that were NVDA's.
